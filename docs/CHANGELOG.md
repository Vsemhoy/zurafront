# Публичная история обновлений

Страница `/changelog` доступна без сессии и без запроса к API. Обе ссылки
на changelog на странице входа ведут сюда. Поиск, модуль и месяц хранятся в URL.

## Источники

`src/entities/changelog/releases.js` — отредактированные описания изменений
по дням. `sources.json` — коммиты обоих репозиториев, использованные при обзоре.
Начальная история: 25 августа — 17 октября 2026; фронтенд `0951b40`,
бэкенд `cfbece6`. Использованы даты авторства (`git log --date=short --format=%ad`).
Это даты изменений в Git, а не обещание даты выкладки на сервер.

Технические коммиты, исправления и повторные правки объединены в понятные
пользователю пункты. Merge-коммиты отдельно не перечисляются. Локальные
незакоммиченные изменения (включая Equip) пока не представлены как обновления.

## Добавление обновлений

1. Просмотреть `git log` и `git show` новых коммитов фронтенда и бэкенда.
   Название `up` не является достаточным описанием: прочитать изменения.
2. Добавить день в начало `releases.js` или дополнить существующий день.
   Каждый пункт — `[модуль, описание]`; список модулей строится автоматически.
3. Добавить `{ "repo": "zurafront" | "zuraback", "hash": "<commit>" }`
   в соответствующий день `sources.json`. Не включать секреты, данные пользователей,
   внутренние адреса или сырые сообщения коммитов в публичные описания.
4. Проверить даты и наличие ссылок, запустить `npm run lint` и `npm run build`,
   открыть `/changelog` на широком и узком экране.

Сборка не публикует Git автоматически: тексты проходят редактуру вместе с кодом.
При новой выкладке страница обновляется с фронтендом, база данных не требуется.
